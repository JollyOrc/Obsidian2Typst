# M31 — Does the delete question start on Delete? (F1 measured in Obsidian2Typst)

Part of the [manual checks](../manual-checks.md).

**When:** before the fix of the confirmation's focus (0.15.3): Game Card Creator measured on Obsidian 1.15.0 that
Obsidian's `Modal.open()` focuses the first focusable element after `onOpen` (its finding F1, #58). This plugin's
`ConfirmModal` (`src/plugin/settings/rows.ts`) creates the warning button first and focuses Cancel in `onOpen`, the
same pattern; it is not measured here yet (SCAR-024, SCAR-045). Again after the fix, with the fixed build.

**Needs:** Obsidian desktop (the author's default environment: M1 MacBook, macOS 27.0.1, Obsidian 1.15.0). Prepared
by the developer (SCAR-012, SCAR-018) in the scratch vault (`spikes/typst-wasm/scratch-vault`):

- **the released 0.15.2** (`main.js` sha256 `0e7da7c4…`, downloaded from the GitHub release and compared byte by
  byte with the installed files), replacing `0.15.1-m29.1`; `data.json` unchanged (active preset `Cards M29`);
- two throwaway presets, copies of `Minimal`: `Obsidian2Typst/presets/M31 Probe A.md` and `M31 Probe B.md`
  (neither is the active preset, so deleting one changes nothing else).

The starting state is `spikes/typst-wasm/m31-before.txt` (315 files, all OK before any change); the `.obsidian` folder
is in `spikes/typst-wasm/m31-state-backup/` (15 files, all OK); the state after the preparation is
`spikes/typst-wasm/m31-handover.txt` (317 files: the two probes added; the plugin's three files changed). Obsidian was
not running during the preparation: **start Obsidian; it opens the scratch vault.**

**Run in the scratch vault** (`spikes/typst-wasm/scratch-vault`). **Expected version:** `0.18.0` (first line of the settings tab, and the plugin list). If it differs, stop.

**Decided before the run (SCAR-032):** F1 is present in this plugin if, in either step, the question opens with the
focus ring on `Delete` or **Enter deletes the probe**. If both steps keep the probe on Enter and show the ring on
Cancel, F1 is not present here, and the fix is not made.

## Steps

1. Settings, Community plugins: Obsidian2Typst **0.15.2**.
2. **(mouse)** Settings, Obsidian2Typst, the preset list: click the gear of **`M31 Probe A`**. In its window, click
   **`Delete`**. The question `Delete preset "M31 Probe A"?` opens. Note which button has the focus ring (if any).
   Press **Enter**. Note: is `M31 Probe A` still in the preset list?
3. **(keyboard)** Click the gear of **`M31 Probe B`**. In its window, press **Tab** until `Delete` has the ring, then
   **Enter**. The question opens. Note which button has the ring. Press **Enter**. Note: is `M31 Probe B` still in the
   list?
4. Send the two answers per step (ring, still there), and **quit Obsidian**. The developer reads the presets folder
   and the trash, then undoes the vault against `m31-before.txt`.

## Results

Run by the owner 2026-11-17 on the released 0.15.2 (M1 MacBook, macOS 27.0.1, Obsidian 1.15.0).

- Step 1: version 0.15.2.
- Step 2 (mouse): no button had a focus ring; **Enter did nothing**; the owner then clicked Cancel; `M31 Probe A`
  stayed. (This differs from Game Card Creator's mouse path, where the focus moved invisibly to the action and
  Enter acted on it; not explained here, not measured further.)
- Step 3 (keyboard): **`Delete` had the focus ring, and Enter deleted the preset.**
- Disk read (SCAR-015): against the hand-over list only `Obsidian2Typst/presets/M31 Probe B.md` is gone (into the
  system trash: no `.trash` in the vault, Obsidian's default for deleted files); `M31 Probe A.md` is there; nothing
  else changed (`data.json` included).
- **By the rule written before the run: F1 is present in this plugin** (the keyboard path). Fix in 0.15.3.
