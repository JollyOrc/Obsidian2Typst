# M22 — The statblock in Obsidian and its API (US-035)

Part of the [manual checks](../manual-checks.md).

**When:** after #134, and after any change to the `o2t-entry` preview, the
statblock model or `styles.css`.

**Needs:** Obsidian desktop. Prepared by the developer (SCAR-012): as M21
(the test build installed in the scratch vault, the sample's new files and
the preset `Entries`). Dataview is not installed in the scratch vault; the
API is called from Obsidian's developer console (step 8). If you want to try
the DataviewJS call as well, install Dataview yourself first (step 9 is
optional).

**Run in the scratch vault** (`spikes/typst-wasm/scratch-vault`). **Expected
version:** `0.14.0` (first line of the settings tab, also the plugin
list). If it differs, stop: the wrong build is installed.

**Known limitations:** the redraw of live preview after a preset change and
the real drawing time were not measured by the tests; this check is where
they are seen.

## Steps

1. Open Settings → Obsidian2Typst. The first line reads `Obsidian2Typst
   0.14.0`. Close the settings. Choose the preset `Entries` in the
   ribbon menu.
2. Open `Sample/Menagerie.md` in **reading view**. Under `### Fen Hare` the
   block is drawn as a statblock: `◆ Fen Hare ◆`, 11 boxes, four cells with
   icons, `Might 5 · Wits 0 · Speed 6`, `Kick 2d6`, **Bite** `1d6`, `Beast`;
   no notice line under it. `Dune Lark` has the line
   `STAT_SUM_MISMATCH: 20 ≠ 4+8+3`. Hovering a cell
   shows nothing to click; clicking a box does nothing.
3. Scroll through the note: it stays smooth. `Quill Rat` shows no boxes and
   the notice `STAT_BOXES_MANY: 46`; `Lamp Wisp` shows its raw block with a
   notice `ENTRY_YAML_INVALID (line N)` above it; the block inside the
   callout `A boxed note` shows `ENTRY_BLOCK_IN_CONTAINER`.
4. Switch to **live preview** (source mode off). With the cursor outside a
   block, it shows the statblock as in reading view; put the cursor into the
   block: the YAML is shown for editing.
5. With the note open in reading view, choose the preset `A5 print` in the
   ribbon menu. At once (no reopening) every block shows its raw YAML with
   `No statblock: the active preset has no entries settings.` above it.
6. Choose `Entries` again: the statblocks come back. Do the same with the
   note in live preview: the statblocks come back there too (or name the
   step at which they did not).
7. Open the preset note `Obsidian2Typst/presets/Entries.md`, change
   `trackLabel: STATE` to `trackLabel: CONDITION` and save. In the open
   `Menagerie.md` the label above the cells reads `CONDITION`. Change it back.
8. Open the developer console (`Ctrl/Cmd + Option/Alt + I`), tab Console, and
   type:
   `const api = app.plugins.plugins["obsidian2typst"].api; api.version`
   → `1`. Then:
   `const el = document.body.createDiv(); const r = await api.renderStatblock(el, {Vigour: 11, might: 4, attacks: ["Kick: 2d6"]}, {heading: "Fen Hare"}); [r.boxes.length, r.cells.map(c => c.getAttribute("aria-label"))]`
   → `[11, ["Fine", "Hurt", "Down", "Gone"]]`. Then `el.remove()`.
9. (Optional, with Dataview installed by you.) A note with
   ```` ```dataviewjs ```` and
   `await app.plugins.plugins["obsidian2typst"].api.renderStatblock(dv.container, {vigour: 5, might: 2, attacks: ["Bite: 1d4"], name: "Marsh Owl"})`
   shows a statblock with `◆ Marsh Owl ◆` and 5 boxes.
10. (US-035 AC-12, #138.) With `Menagerie.md` in reading view, look at
    `Marsh Owl` (16 boxes: 15 in the first row, 1 below box 1) and `Cave
    Wyrm` (45 boxes: three rows of 15). Each row shows three groups of five
    with a wider gap between the groups, and the last box of a full row
    ends inside the right frame line, not on or past it. Then make the
    note's pane narrow (drag the sidebar wider, or split the pane) step by
    step down to about 200 px: the boxes shrink, the groups stay, and no
    box crosses the frame at any step. Do the same in live preview.
    For 0.12.1 this step was not run on a test build: the user waived it
    (2026-11-08) after checking the same CSS rules in Obsidian and in a web
    page export ("looking good"), with the final `styles.css` measured in
    WebKit at 620, 330 and 200 px pages (US-035 AC-12).
11. Is anything missing, odd or ugly that this list did not ask about? Report
    it even if it seems unrelated (SCAR-015).

After the check, the developer restores `Entries.md` from the backup if step
7 left a change.
