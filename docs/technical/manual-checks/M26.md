# M26 — Facing pages open as spreads in your PDF viewers (epic #147)

Part of the [manual checks](../manual-checks.md).

**When:** after #148 and #149 (epic #147, 0.13.1), and after any change to
how the export writes the PDF.

**Needs:** Obsidian desktop, a terminal, and as many PDF viewers as you have
(Preview, Adobe Acrobat, a browser's own viewer, the pdf.js viewer). Prepared
by the developer (SCAR-012): the test build installed in the scratch vault
(`npm run install:scratch`; `main.js`, `manifest.json`, `styles.css`
byte-identical to the fresh build; checksums in the hand-over note), nothing
else changed in the vault; the built-in presets `A5 print` (facing pages on)
and `A4 digital` (off) are in the presets folder. Empty export folders:
`spikes/typst-wasm/m26-export/1` and `spikes/typst-wasm/m26-export/2`. The
vault's state before the install is backed up with a checksum list in the
developer's record (311 files).

**Run in the scratch vault** (`spikes/typst-wasm/scratch-vault`). **Expected
version:** `0.13.1` (first line of the settings tab, also the plugin
list). If it differs, stop: the wrong build is installed. Restart Obsidian
once so the new build is loaded.

**Known limitations (SCAR-024, SCAR-045):** measured by the developer
(2026-11-09): pdf.js 6.5.438 reads the entry through its API and, from its
source, opens a document it has not seen before with page 1 alone and then
2+3 (it does not apply the entry when you have set a spread or scroll
preference, or when the viewer remembers the document; it recognises a
document by its first 1,024 bytes, which two exports of similar books
share, so use a private window or a profile that has not opened an export
of this note before); Apple's PDF parser reads the entry; PDFKit's own view
does not apply it by itself. **Not measured:** Preview, Adobe Acrobat, and
the viewers built into Chrome, Edge and Safari. Those are what this check is
for. The sample's text is generated nonsense.

## Steps

1. Open Settings → Obsidian2Typst. The first line reads `Obsidian2Typst
   0.13.1`. Close the settings.
2. In the ribbon menu choose the preset `A5 print`. Open `Sample/Book.md`
   and run `O2T: Export to PDF` into `spikes/typst-wasm/m26-export/1`. Note
   the number of warnings (not a pass criterion), and that there is no
   `PDF_PAGE_LAYOUT_FAILED` among them.
3. In the terminal, in that folder: `grep -a -c "/PageLayout /TwoPageRight"
   Book.pdf` prints `1`, and `grep -a -c startxref Book.pdf` prints `2` (the
   file Typst wrote, then one update).
4. In the ribbon menu choose the preset `A4 digital` and export the same
   note into `spikes/typst-wasm/m26-export/2`. In that folder `grep -a -c
   PageLayout Book.pdf` prints `0` and `grep -a -c startxref Book.pdf`
   prints `1`: a single-sided export is the PDF as Typst wrote it.
5. **Each viewer, the facing export.** Open `m26-export/1/Book.pdf`. For each
   viewer write down its name and version, then:
   (a) Does it open in a two-page view by itself, with page 1 alone on the
   right and pages 2 and 3 side by side? (The inside margin of an odd page is
   on its left, so page 2 and 3 meet at a wider margin.)
   (b) If it opens in single-page view, switch to its two-page view (Preview:
   View → Two Pages; Acrobat: View → Page Display → Two Page View, with
   "Show Cover Page in Two Page View" off and then on; a browser: the spread
   option). Does page 1 stand alone, and do 2+3, 4+5 pair, in the setting
   that you used? Which setting is it (name it)?
   (c) Does a viewer setting of your own (a default page layout in Acrobat's
   preferences, a remembered view) win over the document? Say which.
6. **Each viewer, the single-sided export.** Open `m26-export/2/Book.pdf` and
   do the same. Expected: nothing asks for spreads; a two-page view, if you
   choose one, pairs as that viewer's default does. Report if it behaves
   differently from `m26-export/1`.
7. **The content is still there (both files, any one viewer).** Page 1 and a
   page in the middle show their text (selectable), the folio and the running
   header where the preset puts them, and the images; a link in the text
   jumps to its target; the outline (bookmarks) is listed in the viewer's
   sidebar; the document title and page count are the same in both files
   (the facing one is not longer by any page).
8. Anything else that looks odd (a viewer warning that the file was
   "repaired" or "modified", a changed page order, a missing bookmark, a
   different first page): note the viewer and what you see.

## Questions for you (US-037, provisional decisions)

- If the update cannot be made, the PDF is written as compiled and the
  report says `PDF_PAGE_LAYOUT_FAILED` (it never stops the export, also in
  strict mode). Is that right?
- A PDF whose catalog already has a page layout keeps it (Typst never writes
  one). Is that right?
- Typst's own `/Direction /L2R`, `/ID` and the rest are left as written.
