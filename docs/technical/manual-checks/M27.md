# M27 — Detail rows: the row under a heading, in the PDF and in Obsidian (epic #152)

Part of the [manual checks](../manual-checks.md).

**When:** after #153 to #155 (epic #152, 0.14.0), and after any change to
the details block, the preset's `details` group, the row's Typst or the
preview and `api.renderDetails`.

**Needs:** Obsidian desktop, the developer console (`Ctrl/Cmd + Option/Alt +
I`) for step 11, and a PDF viewer. Prepared by the developer (SCAR-012): the
test build installed in the scratch vault (`npm run install:scratch`;
`main.js`, `manifest.json`, `styles.css` byte-identical to the fresh build;
checksums in the hand-over note), `Sample/` reinstalled, and these new files
in the vault: the note `Details check.md` at the root (a synthetic note whose
blocks are written the way the Vault Compiler will write them), the folder
`details-check/icons/` with six small SVG icons, and the preset notes
`Obsidian2Typst/presets/Details.md` (four badges, colour `#7a4a2e`, 9.5 pt)
and `Details gray.md` (the same in grayscale). Empty export folders:
`spikes/typst-wasm/m27-export/1`, `/2` and `/3`. The vault's state before the
install is backed up with a checksum list in the developer's record.

**Run in the scratch vault** (`spikes/typst-wasm/scratch-vault`). **Expected
version:** `0.14.0` (first line of the settings tab, also the plugin
list). If it differs, stop: the wrong build is installed. Restart Obsidian
once so the new build is loaded.

**Known limitations (SCAR-024, SCAR-032, SCAR-045):** the Vault Compiler is
not involved: the blocks are written by hand in the form of the contract
`docs/technical/details-block.md`. The page numbers below were measured from
the same note and preset through the plugin's conversion and the bundled
compiler in Node (2026-11-09), not through Obsidian's own export; if a page
number differs by one, look one page further and report it. The row's width
rules were measured by the developer in WebKit (macOS) at widths of 150 to
900 px, not in Obsidian's own engine; step 8 asks you to look. Not measured:
the published site; that Obsidian follows the row's link when you click it
(step 4); live preview's redraw after a preset change (step 7 asks you to try
it). The text is invented.

Read every page at reading size (100 %, SCAR-025) and zoom in on the icons.

## Steps

1. Open Settings → Obsidian2Typst. The first line reads `Obsidian2Typst
   0.14.0`. Close the settings.
2. In the ribbon menu choose the preset `Details`. Open `Details check.md` in
   **reading view**. Each of these headings has one row directly under it, an
   icon and a label each, in this order of badges (pace, kind, requirement,
   flag), in brown text:
   - `Reed Weaving`: Brisk, Craft, Basket Knots (a link);
   - `Basket Knots`: Slow, Lore;
   - `Long Requirement`: Swift, Feat, `has woven for a full season and keeps
     a loom of their own`, Known from the start (the row is two lines, the
     requirement wraps);
   - `Known Already`: Known from the start;
   - `Odd Facts`: `soon` (no icon, printed as written) and `firm hand` (with
     `firm` in bold, with an icon), and under the row a grey line
     `DETAIL_VALUE_UNMAPPED "Odd Facts": pace: soon · DETAIL_VALUE_NOT_TEXT
     "Odd Facts": kind`;
   - `No Facts`: no row (an empty block shows nothing);
   - `Case And Spaces`: Brisk, Lore (written ` BRISK ` and `Kind`);
   - `Plain Heading`: nothing (it has no block);
   - `Level Three` (a `###`): Swift; `Level Five` (a `#####`): Feat, `3`.
3. **Look.** Each icon is as high as a capital letter, sits on the line of
   the text with a small gap before its label, and the badges are about one
   and a half letter widths apart. No table, no code block is shown for any
   of these headings.
4. **The link.** Click `Basket Knots` in the row of `Reed Weaving`: the note
   jumps to the heading `Basket Knots`.
5. **A block that is not read.** In the quote (`A quote with a block
   inside`) the block is shown as code, with the notice
   `DETAIL_BLOCK_IN_CONTAINER` above it, and there is no row.
6. **Other presets.** With the note still open, choose the preset `Details
   gray` in the ribbon menu: every row turns grey (icons and text) at once
   or within a second. Choose `A5 print`: every block shows as code with the
   notice `No details row: the active preset has no details settings.`
   Choose `Details` again: the rows return.
7. **Live preview.** Switch the note to live preview (and back) and do step 6
   once more there. Say whether the rows redraw by themselves or only after
   you switch the view.
8. **Narrow panes.** Drag the note's pane (or the sidebar) narrower, down to
   about 300 px: the long row wraps onto more lines, and no badge reaches
   past the right edge of the text column. Report the narrowest width at
   which you still see nothing cut off.
9. **Export, with rows.** With the preset `Details`, run `O2T: Export to
   PDF` for `Details check.md` into `spikes/typst-wasm/m27-export/1`. The
   report lists exactly these `DETAIL_` warnings (the three
   `HEADING_LEVEL_SKIPPED` lines are not part of this check):
   `DETAIL_VALUE_UNMAPPED "Odd Facts": pace: soon (line 38)`,
   `DETAIL_VALUE_NOT_TEXT "Odd Facts": kind (line 38)` and
   `DETAIL_BLOCK_IN_CONTAINER … (line 78)`.
   Open `Details check.pdf`: 10 pages. Page 1 shows the rows as in step 2,
   in the same brown as the text of the preset; `Basket Knots` in the row of
   `Reed Weaving` is followed by `(p. 1)` and is a link to that heading; the
   long row is two lines; none of the YAML is printed.
10. **Heading, row and text stay together.** From `Page foot` on, twelve
    skills `Foot Skill 1` to `Foot Skill 12` follow filler paragraphs
    (measured pages 2, 3, 4, 4, 5, 6, 6, 7, 8, 8, 9, 10). On every page look
    at the foot: no page ends with a heading alone, or with a heading and its
    row without the first lines of the text. Look at the head of each page:
    a row never stands at the top of a page without its heading.
11. **The API.** Open the developer console, tab Console, and run each line:
    `const api = app.plugins.plugins["obsidian2typst"].api; [api.version,
    typeof api.renderDetails, typeof api.renderStatblock]` → `[1, "function",
    "function"]`;
    `const el = document.body.createDiv(); const r = await
    api.renderDetails(el, {pace: "brisk", kind: "craft", needs: "[[Basket
    Knots]]", starter: true}, {heading: "Reed Weaving"}); [r.badges.length,
    el.textContent]` → `[4, "BriskCraftBasket KnotsKnown from the start"]`;
    then `el.remove()`.
12. **Export, grayscale and no group.** Export the same note with `Details
    gray` into `m27-export/2`: the rows are dark grey (icons and text), the
    same layout and pages as step 9. Export it with `A5 print` into
    `m27-export/3`: no rows, no printed YAML, no `DETAIL_VALUE_` warning
    (only the quote's `DETAIL_BLOCK_IN_CONTAINER`), about 9 pages.
13. Anything else that looks odd, missing or ugly in the rows, the PDF or the
    preview that this list did not ask about? Report it even if it seems
    unrelated (SCAR-015): an icon that is cut off, a label that is missing,
    a row too close to the heading or to the text, a colour that is wrong.

## Questions for you (US-038, decisions made while writing)

- A badge's value is shown only when it is set: `false`, an empty value and
  a missing key show nothing and give no warning. Is that right?
- With **no `details` group in the preset there is no row and no warning**
  (the blocks are read and dropped): one book can be compiled with a preset
  that has no row. Is silence right, or should it be one warning?
- The row is not justified, and a link in it gets its page number under the
  same rule as every other link (including the heading level of
  `linkPageLevel`). Is that right?
- An unmapped value is printed as written, once warned per item.
