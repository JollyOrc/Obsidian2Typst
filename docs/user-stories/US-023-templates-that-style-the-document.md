# US-023 — Templates that style the document

**Status:** Done (2026-10-22)
**Introduced:** v0.9.0 (planned; a new feature bumps the minor version)
**Implemented:** v0.9.0 (test build `0.9.0-m13.1`, M13 passed 2026-10-22)
**Supersedes:** the words "and rules" in US-008 AC-9 (a template's rules never
applied; see AC-1)

---

## Story

**As an** author,
**I want** the template file of my preset to style the whole document —
page colour, heading colours, table colours, footnote font —
**so that** a design such as the Medieval Utilitarian style guide can be
printed without changing the plugin.

Decided by the user (`docs/state/00_governance.md`, 2026-10-22), after the
preset "A5 MU Print" showed that the template part of the style guide could
not be applied: a template defines a function `template(doc)`; the plugin
applies it with `#show: template` right after the template import; on a
conflict the preset (and the Defaults and built-in values under it) wins; a
`#set` or `#show` rule at the top level of a template gets a warning.

Today (measured 2026-10-22 with the plugin's pipeline and the bundled
compiler, scratch probe `mu/probe.test.ts`): the generated document starts
with `#import "template.typ": *` (US-008 AC-9, preamble rule
`template-import`, order 20). A Typst import brings in a file's definitions
(`#let`), never its `#set` and `#show` rules. With a template that sets the
page fill `#FEFCF0`, the text colour `#1A1A1A`, gold level-2 headings
`#C9A44A` and four edge gradients, the PDF had none of them (fills only the
callout colours, 0 shadings); the same rules written into the document gave
all of them. Every reader and writer of the template (by grep, SCAR-017):
`core/convert/preamble.ts` (the import line), `core/template` (scan and
warnings), `core/presets` (the field, the Defaults, `effectiveSettings`),
`plugin/prepare-note.ts` (reads the file, the warnings),
`plugin/run-export.ts` (writes `template.typ`), `plugin/preview/request.ts`
(passes the same file to the preview).

## Acceptance criteria

- **AC-1 (the hook):** When the template defines `template` at the top level —
  a line that starts `#let template` (found as US-008 AC-10 finds
  definitions: at line start, after an optional byte-order mark, `\r\n` or
  `\n` line ends) — the generated document has `#show: template` as the line
  right after the import:
  ```
  // Generated by Obsidian2Typst from "Rules.md". Regenerated on every export.
  #import "template.typ": *
  #show: template
  #set page(width: 154mm, height: 216mm, margin: (top: 23mm, …))
  ```
  for the template
  ```
  #let mu-gold = rgb("#C9A44A")
  #let template(doc) = {
    set page(fill: rgb("#FEFCF0"))
    show heading.where(level: 2): set text(fill: mu-gold)
    doc
  }
  ```
  The template's rules then apply to the whole document (measured: the page
  fill `#fefcf0` and the gold `#c9a44a` are in the PDF).

- **AC-2 (no hook, unchanged):** A template without a top-level `template`
  definition is imported as today and nothing else is written; for example
  `#let accent = rgb("#336699")` gives only `#import "template.typ": *`. No
  template (the field unset in the preset and the Defaults) and a missing
  template (`TEMPLATE_MISSING`, US-008 AC-11) give neither line.

- **AC-3 (the preset wins on a conflict; measured 2026-10-22, placement
  "A"):** The template's rules apply first; every rule the plugin generates
  from the preset, the Defaults or the built-in values comes after them and
  wins for the same property. What the plugin does not generate, the
  template keeps.

  | The template sets | The preset (A5 MU Print) | In the PDF |
  |---|---|---|
  | `set page(fill: rgb("#FEFCF0"))` | no page fill | the page fill `#fefcf0` |
  | `show heading: set text(font: "DejaVu Sans Mono")` | `fonts.heading.family: IM Fell English SC` | the preset's heading font (DejaVu Sans Mono unused) |
  | `set page(margin: 5mm)` | margins 20 / 25 / 23 / 20, bleed 3, gutter 5 | the preset's margins (`top: 23mm, …, inside: 31mm, outside: 23mm`) |
  | `set page(header: align(center)[MU HEADER BAR])` | `runningHeader: false`, `folios: true` | `MU HEADER BAR` at the top of every page, the page number in the footer |
  | the same header | `runningHeader: true` (also the built-in value) | the running title (`Glossary` on page 2), no `MU HEADER BAR` |

- **AC-4 (a hook that is not a function):** `#let template = 5` makes the
  compile fail with the compiler's message at the hook line, shown like
  every compile error (US-007): `expected content or function, found
  integer` at `<note>.typ:3:8` (measured). The plugin does not check the
  value itself (decision 2: left to the compiler).

- **AC-5 (top-level rules get a warning):** For each line of the template
  that starts with `#set` or `#show` (at the start of the line, followed by a
  character that cannot continue a name), the export continues and the
  warning `TEMPLATE_RULE_IGNORED` is reported with the template line, in the
  form of the other template warnings (US-008 AC-10, line 0):
  ```
  template.typ:
  12: #set page(fill: rgb("#FEFCF0"))

  warning: TEMPLATE_RULE_IGNORED  Template rule at line 12 does not apply; put it inside template(doc)
  ```
  The same for `#show heading: set text(fill: red)` and `#show: x`. No
  warning for a rule that does not start the line (`  set page(…)` inside
  `#let template(doc) = {`), for `#showcase()` or `#settings` (other names),
  or for a template without rules. The warning is given with and without the
  hook, because such a rule never applies. A rule at the start of a line
  inside a content block (`#let template(doc) = [` … `#set text(…)` … `]`)
  is warned about although it applies (decision 1: accepted; the
  warning-codes table says so).

- **AC-6 (the name `template`):** `template` is not a Typst standard-library
  name (no `TEMPLATE_SHADOWS_BUILTIN`, US-008 AC-10) and the plugin defines
  nothing named `template` (no `TEMPLATE_NAME_TAKEN`, US-016 AC-11); a text
  check shows that the preamble never defines `template`.

- **AC-7 (the preview is the export):** The preview compiles the same
  document with the same template copy (US-012 AC-13), so the template's
  styling shows in the preview as in the PDF; a test compares the two
  documents with a hook template.

- **AC-8 (composed, SCAR-002):** With the hook template of A5 MU Print (page
  fill, edge gradients in the background, text colour, heading colours,
  table fills, a footnote font, a section-divider colour), a note with every
  kind of content compiles and keeps its content: headings 1 to 4, a
  paragraph with a footnote, bold and inline code, a thematic break, an
  `example` callout with a list, a table of 3 and one of 14 rows, a nested
  list, a glossary section with a term, an internal link with its page
  number (`#link(<h-tessera>)[Tessera]#page-ref(<h-tessera>)`), and an image in
  first position that becomes the cover (`cover.mode: auto`). Measured
  2026-10-22: no diagnostics; 3 pages; the texts of the note; the fills
  `#fefcf0`, `#1a1a1a`, `#c9a44a` (template), `#fbe2c5`, `#7a4a2e` (the
  preset's callouts); the four edge fades, each a gradient to transparent
  with its mask (8 shading objects; amended after M13, 2026-10-22: opaque
  strips left seams where they overlapped); page 1 is the cover image only, edge to
  edge, without header, footer or visible gradient; page 2 has no header
  (it starts with a level-1 heading) and the page number 1; page 3 has the
  running title `Glossary` and the page number 2.

- **AC-9 (where the template comes from, SCAR-019):** The hook works the same
  for a template set in the preset, a template set only in the Defaults, and
  is absent when neither sets one or the file is missing (AC-2).

- **AC-10 (US-008 AC-9 corrected):** US-008 AC-9 says "so the template's
  functions and rules are available"; it is corrected to "the template's
  definitions are available; its rules apply through `template(doc)`
  (US-023)".

- **AC-11 (the MU template and the manual check):** The scratch vault gets
  the template `Obsidian2Typst/templates/A5 MU Print.typ` (from the measured
  draft) and the preset "A5 MU Print" selects it. A manual check, in
  Obsidian, with the preview and an export, names what the page must show:
  the parchment colour with the fade at the page edges, the gold level-2
  headings, the blue thematic break, the gold table header with alternating
  rows, the umber callout box, the preset's margins and page numbers; and the
  warning of AC-5 for a template with a top-level rule (SCAR-015).

## Decisions (answered 2026-10-22)

1. **A rule at the start of a line inside a content block** (AC-5).
   *Decided: accept and document it.* The scan
   reads lines, as the definition scan of US-008 AC-10 does; it cannot tell a
   top-level `#set` from one inside `[` … `]`. Proposed: accept the extra
   warning and say in the warning-codes table that a content-block template
   gets it (the usual form `{ set …; doc }` does not). Alternative: count
   brackets, strings and comments to know the depth (a small parser of
   Typst).
2. **A hook that is not a function** (AC-4). *Decided: leave it to the
   compiler.* Proposed: leave it to the
   compiler, whose message names the line. Alternative: the scan accepts
   only `#let template(` and warns `TEMPLATE_HOOK_NOT_FUNCTION` for any other
   form (`#let template = …`), and the plugin then writes no hook line.

## Notes

- Measured 2026-10-22 (scratch probe `mu/probe.test.ts`, page images): the
  hook right after the import ("A") keeps the preset's geometry and fonts;
  the hook before the body ("B") let a template's `margin: 5mm` replace the
  margins and the bleed, and its heading font replace the preset's. The user
  chose A.
- New call sites (SCAR-001): `scanDefinitions` (the hook name), the preamble's
  template rule, `templateWarnings` (a third code).
- Worst misplaced click (SCAR-014): none; nothing is written into the vault.
- Out of this story: ornaments, columns, spread breaks, margin notes,
  illuminated initials (the backlog topics "Decoration", "Page breaks and
  structure"); a template that styles the cover page differently.
