# Obsidian2Typst v0.15.3

**Release date:** 2026-11-17
**Minimum Obsidian version:** 1.5.0 (desktop only)
**Tests:** 2633 unit, plugin and tooling tests passed, 1 `todo`; 692/692 integration tests passing (working tree; the clean-clone gate of the release build is recorded in the project's state files)

The questions before deleting a preset or resetting a value now really start on **Cancel**.

---

## Fixes

- **Enter in a confirmation question acted on the destructive button** (#174):
  the questions `Delete preset "…"?`, `Reset "…"?` and the reset of the
  preview panel put the focus on `Cancel` while opening, but Obsidian then
  moves the focus to the dialog's first button, which was `Delete` or
  `Reset`. After keyboard use (the focus ring showed on `Delete`), Enter
  deleted the preset; the note went to the trash. `Cancel` is now the first
  button, so the focus and Enter stay on it. Escape and the buttons work as
  before.

## Changed behaviour

- The questions show **`Cancel` first**, then `Delete` / `Reset`.

## Limits

- Tested on: Obsidian 1.15.0 on macOS (Apple silicon), in a scratch vault
  (manual check M31: the defect on 0.15.2 by keyboard and by mouse, and the
  re-check of the fix on both paths). With the mouse, 0.15.2 showed no focus
  ring and Enter did nothing; that difference is recorded, not explained. Not
  tested: Windows, Linux, mobile, other Obsidian versions.

None.
