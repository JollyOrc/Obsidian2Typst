# Obsidian2Typst v0.15.1

**Release date:** 2026-11-13
**Minimum Obsidian version:** 1.5.0 (desktop only)
**Tests:** 2614 unit, plugin and tooling tests passed, 5 skipped, 1 `todo` (clean-clone gate of 2026-11-13; 2619 passed in the working tree, where the git-ignored state files and word list, which five tests need, are present); 676/676 integration tests passing

A fix for callers of `api.statblockTypst`: one icon path now always means one
file.

---

## What changes

- **Numbered icon files** (US-040): in the answer of `api.statblockTypst`, the
  `n` of `o2t-icons/<n>.svg` is the 1-based position of the icon in the
  preset's statblock `track` (until 0.15.0 it counted in the order of first
  use within one answer, so one path could be different files in different
  answers). The same vault icon still gives one entry; a missing icon keeps
  its number; the numbers need not be consecutive.
- The PDF export, `renderStatblock`, `renderDetails` and the preview are
  unchanged. `api.version` stays 1.

## Breaking changes and migration

A caller that read the numbers as "1 to the count" must read the paths from
`data`. Under the example preset (track Fine, Hurt, Down, Fading, Gone) the
default statblock now names `1`, `2`, `3` and `5`.
