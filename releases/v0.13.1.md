# Obsidian2Typst v0.13.1

**Release date:** 2026-11-09
**Minimum Obsidian version:** 1.5.0 (desktop only)
**Tests:** 2423/2423 unit, plugin and tooling tests passing (1 `todo`
marker, as before); 641/641 integration tests passing (gate of 2026-11-09)

Facing pages open as spreads (epic #147, US-037): the PDF of an export with
facing pages asks a PDF viewer to open as spreads, so a two-page view shows
page 1 alone and then pages 2 and 3, 4 and 5, as the book is laid out.

---

## What changes

- With `facingPages: true` the book's PDF is written with the page-layout
  setting `TwoPageRight` (an incremental update after the file Typst writes;
  nothing before it changes). Exports without facing pages, and the A4
  encounter sheet, are written as compiled.
- The checks that read the PDF afterwards (the word-gap scan) read the
  written file and give the same results.
- A PDF that is not in the form Typst 0.14.2 writes is written as compiled
  and the report says `PDF_PAGE_LAYOUT_FAILED`; it never stops an export,
  also in strict mode.
- A PDF whose catalog already has a page-layout setting keeps it. The
  document ID and the rest of the catalog stay as Typst wrote them.

## Breaking changes and migration

None. No new setting; `data.json` and preset notes keep their format. Only
the PDF of an export with facing pages differs: it opens as spreads in a
viewer that reads the setting.

## Known limits

- The setting is the view the document opens in. A viewer's own setting or
  a remembered view of the document may win; the viewers measured are pdf.js
  and Apple's PDF parser. Preview and Adobe Acrobat were not measured by
  the compiler's tests; manual check M26 passed on the same `main.js`.
