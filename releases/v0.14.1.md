# Obsidian2Typst v0.14.1

**Release date:** 2026-11-10
**Minimum Obsidian version:** 1.5.0 (desktop only)
**Tests:** 2567/2567 unit, plugin and tooling tests passing (1 `todo`
marker, as before); 672/672 integration tests passing (gate of 2026-11-10)

A bug-fix release: the text beside a statblock, the encounter sheet's icon
key, and two fixes in the project's own example data and checks.

---

## What changes

- **Text beside a statblock reads as one paragraph** (#160, US-030 AC-16c).
  Where the opening text is split at the statblock, the rest used to start
  below it after a hole of up to about one and a half lines. Now the column
  beside the statblock ends at the statblock's lower edge (it takes the
  nearer number of lines, then its line spacing changes by at most a tenth of
  a line), and the text below continues at the normal line spacing, not the
  paragraph spacing. A paragraph that fits beside the statblock within half a
  line goes there whole. The portrait page layouts that place a picture
  after this text measure the space correctly.
- **The encounter sheet's icon key keeps each icon with its label** (#157,
  US-036 AC-7a). Each icon and its label form one item that is never split;
  the gap between items shrinks from 4 mm down to 1.5 mm before the key wraps
  to a second line; the icons sit centred on the text instead of standing on
  the line. The key is measured in the statblock's text font when a preset
  sets one. Applies to the sheet page in the book and the A4 sheet file.
- The example e-mail address in the link documentation and its tests is an
  invented one (#159).
- The project's check that every manual check names the right build version
  reads the check's "Expected version" sentence, not any version in the file
  (#158). No change for users.

## Breaking changes and migration

None. Exports change where a statblock splits a paragraph (the text after
it moves up) and where an encounter sheet's key wrapped or its icons stood
on the line. Other exports are unchanged.

## Known limits

- The join below the statblock was checked in the scratch vault with the
  sample presets, plain and justified (manual check M28, part A). The check
  with the author's own preset (part B) was not run.
- Where the column beside a statblock is short (a few lines) and would need
  more than a tenth of a line of extra spacing, its spacing stays as it is
  and it may end up to half a line above the statblock's lower edge.
