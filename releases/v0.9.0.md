## New: templates that style the document (US-023)

A preset's template file can now style the whole document. Until now a
template could only supply definitions (helper functions); its `#set` and
`#show` rules never reached the document.

- Define a function `template` in the template file:

  ```typst
  #let template(doc) = {
    set page(fill: rgb("#FEFCF0"))
    show heading.where(level: 2): set text(fill: rgb("#C9A44A"))
    doc
  }
  ```

  The plugin then writes `#show: template` right after the template import,
  so the rules apply to the whole document, in the export and in the
  preview alike.
- **The preset wins on a conflict.** Rules the plugin generates from the
  preset, the Defaults or the built-in values (fonts, page size, margins,
  bleed, running header, page numbers) come after the template's and win for
  the same property. The template adds what the preset does not set: page
  colour and background, text and heading colours, table colours, line
  styles. Example: a template header shows only when the preset turns its
  running header off.
- **New warning `TEMPLATE_RULE_IGNORED`:** a `#set` or `#show` at the top
  level of a template, which never applies, is reported with its line:
  `Template rule at line 12 does not apply; put it inside template(doc)`. A
  rule at line start inside a content block (`= [ … ]`) gets the warning too,
  although it applies (a documented limit).
- A `template` that is not a function makes the compile fail with Typst's own
  message at the hook line.
- A template without `template` behaves as before.

## Changed behaviour and corrections

- US-008 AC-9 said the template's "functions and rules are available"; it
  now says the definitions are available and the rules apply through
  `template(doc)`.
- The template warnings (`TEMPLATE_SHADOWS_BUILTIN`, `TEMPLATE_NAME_TAKEN`,
  `TEMPLATE_RULE_IGNORED`) are listed in the order of the template's lines.

## Breaking changes and migration

None. Templates without a `template` function work as before. A template
that relied on top-level rules never had them applied; move them into
`#let template(doc) = { … doc }` to make them work. Such templates now get
`TEMPLATE_RULE_IGNORED`.

## Presets that ship

Unchanged from 0.8.0: `A5 print` and `A4 digital`, created only when the
presets folder does not exist. The preset "A5 MU Print" (the Medieval
Utilitarian look) and its template were built for the manual check M13 and
live in the project's test vault; they do not ship.

## Known limitations

As in 0.8.0 (desktop only; remote images not downloaded; no PDF/A, PDF/UA,
PDF/X; menu items act on the cursor's line; the compiler does not report a
missing font family), plus:

- The template warning scan reads lines; a rule at line start inside a
  content-block template is warned about although it applies.
- A template cannot override a property the plugin generates (the preset
  wins by design).
