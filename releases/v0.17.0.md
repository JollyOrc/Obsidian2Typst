# Obsidian2Typst v0.17.0

**Release date:** 2026-11-25
**Minimum Obsidian version:** 1.5.0 (desktop only)
**Tests:** 2898 unit, plugin and tooling tests passed, 1 `todo`; 707/707 integration tests passing (working tree; the clean-clone gate of the release build is recorded in the project's state files)

Encounter sheets you can print before the session: every creature of a room on its own row, already filled in.

---

## New features

- **Prefilled encounter rows** from an `o2t-encounter` block (written by the Obsidian Vault Compiler 0.26.0 from an
  `[!encounter]` callout of a room note; format in `docs/technical/encounter-block.md`). Where the block stands, one
  framed row per creature: the name (numbered when there are several: `Fen Hare 1`, `Fen Hare 2`; no two rows of a
  block alike), the note of its line, the attributes of `entries.statblock.stats` filled in, the traits that are set,
  **exactly as many tick boxes as its box value** (up to 45), its own state track (none for `none`), every attack, and
  a NOTES line. A dice count (`1d4`) gives the highest roll's number of rows and notes `1d4 (up to 4)`. A creature
  without data gets a blank row (the encounter sheet's row with its name). Two rows across when two 88 mm rows fit
  (an A4 page), else one; a row never splits over a page. Drawn in the statblock's look; nothing is printed inside a
  box, a cell or the notes line.
- Seven new warnings: `ENCOUNTER_YAML_INVALID`, `ENCOUNTER_KEY_UNKNOWN`, `ENCOUNTER_COUNT_INVALID`,
  `ENCOUNTER_COUNT_CAPPED`, `ENCOUNTER_BOXES_CAPPED`, `ENCOUNTER_IN_CONTAINER`, `ENCOUNTER_NO_STATBLOCK`.

## Changed behaviour

- None for notes without an `o2t-encounter` block. The blank encounter sheet (US-036) is unchanged.

## Limits

- In Obsidian's reading view the block shows as a code block; the rows are in the PDF and the preview panel.

## Breaking changes and migration

- None.
