# Obsidian2Typst v0.12.0

**Status:** draft — not released. Test build `0.12.0-m21.1` is in the
manual checks M21 to M24; the release follows when they pass.
**Release date:** —
**Minimum Obsidian version:** 1.5.0 (desktop only)
**Tests:** 2347/2347 unit, plugin and tooling tests passing (1 `todo`
marker, as before); 598/598 integration tests passing (gate of 2026-11-07,
test build `0.12.0-m21.1`)

Entries: creatures, items and anything else with numbers get a statblock,
and inside an entries chapter a page or a spread of their own with their
illustration, laid out on facing pages. A quick reference table and a
printable encounter sheet follow each chapter; Obsidian draws the same
statblock in reading view. Two print checks warn about coarse images and
wide word gaps. Notes without entries export as before; the print
resolution check is new for every export (see "Changed").

---

## New: the entry block and the statblock (US-030)

- A fenced block ```` ```o2t-entry ```` under a heading holds the entry's
  data as YAML. It is never printed as it is.
- The preset's `entries.statblock` names the stats, traits, the box key, the
  state track (with SVG icons) and the look; `entries.tagLabels` the tags;
  `colorMode: grayscale` prints it in gray. The statblock sits beside the
  entry's opening paragraph and is never split.
- Data checks: too many boxes, an unknown track cell, an unmapped tag, a sum
  that does not add up, an attack without dice.

## New: entries chapters and their layouts (US-031, US-032, US-033)

- `headingRules: {Menagerie: entries}` makes a chapter of entries. Seven
  layouts — `page-text`, `page-landscape`, `page-portrait`, `spread-text`,
  `spread-landscape`, `spread-portrait`, `full-image` — or `auto`, which
  chooses by the illustration and by what fits.
- Page entries pair up on facing pages; spreads start on a left page;
  illustrations scale to fit and may shrink to `entries.image.minScale`. An
  entry that runs over says `<heading> (continued)` in the header.
- Sections open on right pages; the chapter's entries are listed in the
  contents and in the running header's section titles; links to entries get
  page numbers.
- `entries.quickReference: true` adds a table of every entry after the
  chapter.

## New: the encounter sheet (US-036)

- `entries.encounterSheet: true`: a page of blank tracker rows after each
  entries chapter. `entries.encounterSheetFile: true`: the same as an A4 file,
  `<note> - Encounter Sheet.pdf`, next to the book's PDF.

## New: the statblock in Obsidian and its API (US-035)

- Reading view and live preview draw `o2t-entry` blocks as statblocks with the
  active preset, and redraw when the preset changes.
- `app.plugins.plugins["obsidian2typst"].api` (version 1):
  `renderStatblock(el, data, options)` for your own views, such as an
  encounter tracker in DataviewJS.

## New: print checks (US-034)

- `images.minDpi` (built-in 300; 0 = off; the row **Print resolution**):
  `IMAGE_LOW_DPI` for every block image and the cover below it, in the export
  and the preview.
- When the template justifies the text, narrow columns are set with
  `entries.narrowJustification`, and the export scans the PDF for wide word
  gaps (`entries.maxWordGap`, built-in 200 %): `TEXT_WIDE_GAP` quotes the line.

## Changed

- **Every export** now checks image resolution at 300 dpi. A book with
  small images gets `IMAGE_LOW_DPI` warnings it did not get before; they never
  stop an export. Set `images.minDpi: 0` to switch the check off.
- The Strict mode row reads `Conversion warnings abort the export.`: the
  warnings found after the compile (image fit, layout, print checks) never
  did and never do.

## Breaking changes

None. Presets without `entries` give the same output as before, apart from
the resolution warnings above.
